Expand description

One language target: its name, its rendering, and the hooks the build, package, and generate --dev commands call.

Rendering is pure: render returns files in memory with paths relative to the target’s own output directory ({out}/{name}/), and the Orchestrator does the I/O.

Provided Methods§

Source

fn package( &self, model: &Model, ctx: &PackageContext<'_>, ) -> Result<Vec<Artifact>>

The installable artifacts that bundle the per-platform builds in ctx, with paths relative to the dist directory.

A target skips platforms its ecosystem has no slot for and returns an empty list when none of the builds fits. A target that needs an external tool which isn’t installed records the artifact it skips with PackageContext::skip instead of failing. The default packages nothing.

§Errors

Returns an error when a library can’t be read or an external tool that is installed fails.

Source

fn finish_package( &self, dist: &Utf8Path, artifacts: &[Artifact], ctx: &PackageContext<'_>, ) -> Result<Vec<Utf8PathBuf>>

Finish packaging after package’s artifacts are written to dist (for example, dotnet pack over the written project), returning any further files written, relative to dist. The default does nothing.

§Errors

Returns an error when an installed external tool fails.

Source

fn dev_bundle_dir(&self, model: &Model) -> Option<Utf8PathBuf>

Where weaveffi generate --dev copies the producer’s library so the generated package finds it without setup, relative to the target’s output directory, or None when the package doesn’t bundle one.

Source

fn linkage(&self) -> Linkage

How the bindings find the producer’s library during development. The default is Linkage::Runtime.

Source

fn fixed_files(&self) -> &'static [&'static str]

The files (by file name, or by suffix for a pattern starting with *) whose contents don’t depend on the API beyond its names: fixed runtimes, package manifests, and READMEs.
