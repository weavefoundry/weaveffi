Expand description

A WeaveFFI API definition: the root of a parsed IDL document.

An IDL file deserializes into this type (see crate::parse), and a Rust producer’s metadata frames assemble into one (see crate::meta). Every declaration lives in the library’s single namespace.

Fields§

§version: String

The IR schema version this document targets (0.13.0).

§doc: Option<String>

Documentation for the library as a whole, propagated to each package’s top-level doc comment.

§imports: Vec<String>

Other IDL files whose declarations join this library’s namespace, as paths relative to this file. crate::parse::load_api resolves them; a document assembled in memory has none.

§records: Vec<RecordDef>

Records: plain data types with named fields.

§enums: Vec<EnumDef>

Enums, C-style or with data-carrying variants.

§errors: Vec<ErrorDomain>

Error domains: named, open sets of error codes that callables report by naming the domain in their throws.

§interfaces: Vec<InterfaceDef>

Interfaces: reference-counted object types with constructors, methods, and statics.

§callbacks: Vec<CallbackDef>

Callback interfaces: method sets the consumer implements and the producer calls.

§functions: Vec<Function>

Free functions.

pub fn for_each_type_ref<'a>(&'a self, f: &mut dyn FnMut(&'a TypeRef))

Call f on every type reference written anywhere in the document: parameters and returns of every function, interface member, and callback method, and the fields of every record, enum variant, and error code (outermost references only; use TypeRef::walk to reach nested ones).

Every top-level declaration’s name, in document order: records, enums, error domains, interfaces, callback interfaces, then free functions.
