WeaveFFI (dev)

Python

The Python target produces a pip-installable package of pure-Python ctypes bindings over the C ABI (revision 6). There’s no compilation step, no native extension, and no third-party runtime dependency; the package works on any Python 3.10+ interpreter that can load the producer library. The implementation module is fully annotated and the package ships py.typed, so type checkers read the bindings themselves (there’s no separate stub to drift out of date), and the generated code is written to pass mypy --strict.

Every value crosses the boundary as one C value. Records and rich enums are frozen dataclasses that cross as value buffers. Interfaces are reference-counted wrapper classes with a context manager. Error domains are exception classes. Callback interfaces are abstract base classes the consumer subclasses. Async functions are coroutines whose cancellation cancels the native call, and iter<T> returns are lazy NativeIterator[T] objects.

Python is a Tier 1 target: it tracks every ABI revision as it lands and runs the full conformance suite in CI.

What gets generated

For the kvstore sample (package name kvstore, C prefix kvstore):

python/
├── pyproject.toml          # PEP 621 metadata, built with setuptools
├── README.md
└── kvstore/                # the import package, named after the C prefix
    ├── __init__.py         # re-exports the module's __all__
    ├── kvstore.py          # runtime, prototypes, and wrappers
    └── py.typed            # PEP 561 marker

The distribution name is the package identity’s name and the import package is its C prefix, so a crate named key-store installs as key-store and imports as key_store. Both are configurable:

[generators.python]
name = "kvstore-python"      # distribution name (default: package name)
import_name = "kvstore_py"   # import package (default: C prefix)
requires_python = ">=3.12"   # default ">=3.10"

A library is one namespace, and so is the package: every record, enum, error class, interface, callback interface, and free function is exported from the package itself under its IDL name (functions in snake case). The module lists its public names in __all__ (the error classes, LibraryLoadError, NativeIterator, every type, and the free functions), so from kvstore import * and the package’s __init__.py export the API and none of the runtime’s helpers. Annotations use builtin generics and X | None.

Install and load

weaveffi generate -o bindings --target python   # in the producer crate
pip install bindings/python

At import, the module loads the producer library from the first of:

  1. the path in {PREFIX}_LIBRARY (for example KVSTORE_LIBRARY),
  2. a library bundled inside the package directory (what weaveffi package produces, and where weaveffi generate --dev copies the debug build), and
  3. the system loader’s search path, by platform file name (libkvstore.dylib, libkvstore.so, or kvstore.dll).

It then makes the two load-time checks before binding anything else. kvstore_abi_version() must report revision 6, and every declaration the bindings were generated with (every function, interface member, type, error code, and callback method) must have its contract function in the library, returning the hash the bindings embed. The module holds one row per declaration: the contract function, the hash, and the declaration’s path, with its canonical signature:

_CONTRACT: list[tuple[str, int, str]] = [
    ("kvstore_contract_c6c5d9ee1b7cfa9e", 0x36b344095a0f5bf9, "Store.rank"),  # method rank(Scorer) -> [string] throws KvError
    ...
]

When the library can’t be loaded, or a check fails, the import raises LibraryLoadError, an ImportError subclass whose message says what went wrong and whose path names the library:

kvstore.kvstore.LibraryLoadError: Store.put changed since these bindings were generated (/opt/lib/libkvstore.dylib)

The other messages are Store.put is missing from the library, a C ABI mismatch naming both revisions, a library that doesn’t export kvstore_abi_version, and the loader’s own error with a hint to set KVSTORE_LIBRARY. A stale binding never misreads a buffer at runtime. Declarations the library has and the bindings don’t are fine, so a library that grew new functions, error codes, or callback methods still loads. Since the failure happens during the import, catch it as ImportError around the import statement.

Every C prototype is then bound once, in a module-level table:

_c_Store_count = _bind("kvstore_Store_count", ctypes.c_uint64, ctypes.c_void_p, ctypes.POINTER(_ErrorStruct))

On macOS, the system python3 strips DYLD_LIBRARY_PATH, so prefer {PREFIX}_LIBRARY there.

Type mapping

Parameters accept abstract containers (any Sequence or Mapping) and returns hand out concrete ones (list, dict). Every value is one C value in every position (a parameter, a return, an async result, an iterator item, and a callback method’s arguments and return), and the runtime mirrors the C structures as ctypes.Structure subclasses passed and returned by value: _Run for {prefix}_run (a pointer and a byte length) and _OptI32, _OptF64, and so on for each {prefix}_opt_{prim} (a presence flag and a value).

ctypes truncates an out-of-range integer to the parameter’s C width without a word, so every integer argument is checked first: a value out of range raises OverflowError naming the parameter (a: 2147483648 is out of range for i32), and a non-integer raises TypeError. The checks run before anything is lent or registered for the call, so a failed check leaks nothing.

An optional scalar (i64?, bool?, Priority?) never touches a value buffer: None passes an absent _Opt{Prim}, and a returned one becomes the value or None. A numeric list parameter accepts any sequence or iterable of numbers (a list, a tuple, a range, a generator); it’s packed into an array.array with range checks, whose buffer Python aligns for every element type, and lent to the call. An array.array of the matching type code is lent as is, without a copy. A str or bytes argument is refused rather than reinterpreted. Returned typed arrays are copied into a list and released.

Strings and bytes pass without per-byte loops: a str is encoded once and its bytes are lent to the call as a run, so interior NUL characters survive. Returned strings, bytes, typed arrays, and buffers are copied with ctypes.string_at and released with {prefix}_run_free.

Every record and rich enum has one writer and one reader function (_write_Entry, _read_Entry), and so does every distinct composite type the API uses, named by the composite’s canonical stem (_write_list_string, _read_map_string_Store, _read_opt_Entry); a call site makes one call instead of inlining a loop. Lists of a fixed-width number type inside a buffer are packed and unpacked with one struct call. A value out of range for its field raises OverflowError while encoding. A decoded buffer that’s truncated, has trailing bytes, an invalid flag, invalid UTF-8, an undeclared enum value, or a repeated map key raises InternalError with code -3.

Records are @dataclass(frozen=True, slots=True): they compare and hash by value (a record holding a list or dict field compares by value but can’t be hashed), and a changed copy comes from dataclasses.replace:

entry = store.get("alpha")
renamed = dataclasses.replace(entry, tags=["archived"])

Rich-enum variants work with isinstance and with match:

match change:
    case kvstore.ChangePut(entry=entry, replaced=True):
        print("replaced", entry.key)
    case kvstore.ChangeRemoved(key=key):
        print("removed", key)

The module starts with from __future__ import annotations, so annotations name types declared later in the file without quotes. Backticked identifiers in IDL docs and deprecation messages are rewritten to their Python spellings in docstrings and DeprecationWarnings.

Objects and lifetime

An interface wrapper holds one strong reference and releases it exactly once: from close(), the with statement, or the __del__ backstop. close() is idempotent, and using a closed wrapper raises ValueError. Each call lends the pointer for its duration, so close() from another thread while a call is in flight defers the release until the call returns. Two wrappers compare equal (and hash alike) when they hold the same native object, so store.share() == store and a record holding a Store compares by identity. An interface member named close is close_, so it never replaces the wrapper’s own (reserved member names).

A constructor named new becomes __init__; other constructors are @classmethod factories:

    @classmethod
    def open(cls, path: str) -> Store:
        _err = _ErrorStruct()
        _ret = _c_Store_open(_run_in(path.encode("utf-8")), ctypes.byref(_err))
        if _err.code:
            raise _kv_error_from(*_read_error(_err))
        return cls._adopt(_required(_ret))

Objects returned by the producer, decoded from a buffer, or passed to a callback are adopted into new wrappers. Writing an object into a value buffer (a record field or a list element) mints a new reference only after the whole argument list has encoded, so a failed encoding leaks nothing.

Errors

Every declared error derives from the package’s root Error (named {PascalName}Error if the API declares its own Error type), which carries code and message. Each error domain is a subclass named by the shared rule (KvError stays KvError, KitchenErrors becomes KitchenError, Failure becomes FailureError). Each code is a subclass of its domain named {Code}Error (KeyNotFoundError), also reachable as KvError.KeyNotFound, carrying its stable CODE. When {Code}Error would shadow a Python builtin (TimeoutError) or another declaration, it’s qualified with the domain’s stem (KvTimeoutError). A code’s payload fields are constructor arguments and attributes; a field named like an exception attribute (message, code, args) gets a trailing _:

try:
    store.get("nope")
except kvstore.KvError.KeyNotFound as e:
    print(e.code, e.key, e.message)  # 1001 nope key not found: nope

What a failed call raises follows its throws:

  • throws: SomeDomain: the code’s class. Codes are matched within the callable’s domain, so two domains may reuse a value. Domains are open: a positive code these bindings don’t know (from a newer library) raises the domain’s base class with its code and message.
  • throws: any: the root Error with code -1 and the producer’s message.
  • A negative code on a throwing call (a panic, a marshalling failure, or a failed callback) raises the root Error with that code; the constants are GENERIC_ERROR_CODE (-1), PANIC_ERROR_CODE (-2), MARSHAL_ERROR_CODE (-3), and FOREIGN_ERROR_CODE (-4).

A call that declares no errors can only fail through a bug, so it follows the trap policy: it raises InternalError, a RuntimeError subclass outside the Error hierarchy whose message names the code and the producer’s message (InternalError: (-3) ...). A cancelled async call (-5) raises asyncio.CancelledError instead.

Each call passes a fresh error slot, which the producer overwrites. Error messages cross as UTF-8 bytes plus a length, so they may contain any character; an empty message is "".

Async and cancellation

An async function is an async def that must run on an asyncio event loop. The launcher receives a static completion trampoline and an integer key; the trampoline takes ownership of the result (one C value, like a sync return) on the producer’s thread and settles the future through call_soon_threadsafe:

async def open_store(path: str) -> Store:
    _call, _future = _async_begin()
    try:
        _c_open_store(_run_in(path.encode("utf-8")), _open_store_completion, _call)
    except BaseException:
        _async_abandon(_call)
        raise
    _result: Store = await _future
    return _result

The launcher copies everything it needs before it returns, so the arguments’ memory needn’t outlive the call.

For a cancellable function, each call owns a native cancel token. Cancelling the awaiting task (directly, through asyncio.wait_for, or by cancelling a gather) cancels the token, waits for the producer’s cancelled completion, and raises asyncio.CancelledError. Cancelling the task awaiting a function that isn’t cancellable stops the wait only; the native call runs to completion and its result is dropped.

Callbacks

A callback interface is an abc.ABC with one abstract method per IDL method. Passing an instance registers it in a handle table under an integer key, and the call passes the producer a _{Name}Arg structure holding that key as ctx and the address of the interface’s one vtable; None for an optional callback parameter passes a null vtable. The vtable is built the first time an implementation is passed and kept for the process lifetime. It starts with the header (its size, flags, and the shared free entry), and the producer’s free(ctx) removes the table entry, so an implementation lives exactly as long as the producer holds it. flags is 0: the producer may call any method from any thread.

Each method’s vtable entry is a trampoline that takes the method’s C arguments and returns its one C value. A ctypes callback can’t return a structure, so a method returning a _Run (a string, bytes, typed array, or buffered value) or an _Opt{Prim} is a libffi closure the runtime builds directly, through the libffi ctypes itself runs on; every other method is a plain ctypes callback.

Trampolines run on whichever thread the producer calls from; ctypes acquires the GIL first. A trampoline adopts the object arguments first, converts the rest (an optional scalar arrives as T | None, a typed array as a list, and a run is copied, since it’s only lent), calls the method, and returns:

  • a number, bool, or enum, checked for its type and range inside the trampoline (so a wrong return is reported as a failure rather than truncated);
  • an optional scalar as its _Opt{Prim};
  • an object as a fresh strong reference the producer adopts (None is allowed only for I?);
  • a str, bytes, typed array, record, or other buffered value as a run allocated with {prefix}_alloc, which the producer adopts and frees.
def _Loader_load(ctx: int | None, key: _Run, out_err: int | None) -> _Run:
    try:
        _ret = _callback_get(ctx).load(_peek_str(key))
        return _alloc_run(bytes(_ret))
    except BaseException as exc:
        _callback_fail(out_err, exc, _GENERIC, KvError)
        return _Run()

Nothing unwinds through C. A method that throws a domain may raise that domain’s codes, which reach the producer as that code with the fields as the error payload ({prefix}_error_set and {prefix}_error_set_payload):

class EmptyLoader(kvstore.Loader):
    def name(self) -> str:
        return "empty"

    def fallback(self, key: str) -> kvstore.Store | None:
        return None

    def load(self, key: str) -> bytes:
        raise kvstore.KeyNotFoundError(key=key)

A Rust producer decodes such a code into its typed error, so the caller of the original function sees the domain’s own message rendered from the fields. Any other exception, or a return of the wrong type, reaches the producer as code -1 with the exception’s message (-4 for a method that declares no errors); a Rust producer receives it as a ForeignError, which the kvstore sample turns into KvError.CallbackFailed.

Iterators

An iter<T> return is a NativeIterator[T], a lazy iterator: each next() makes one native next call through the pre-bound function, receiving the item in one out slot of its C type, and the handle is released on exhaustion, close(), the end of a with block, or garbage collection. A closed iterator is exhausted.

for key in store.keys(None):
    print(key)

with store.entries("user.") as entries:
    first = next(entries)   # the rest is released when the block ends

Packaging

weaveffi package --target python writes one wheel per desktop platform built, python/{name}-{version}-py3-none-{platform}.whl (the distribution name escaped for a wheel file name, so Key-Store becomes key_store), with the producer library inside the import package. The platform tag matches the build: the [build] macOS deployment target (macosx_11_0_arm64), the newest glibc the library links against on Linux (manylinux_2_17_x86_64 or later), or win_amd64. The wheels install with pip and upload with twine; Android, iOS, and wasm32 builds have no wheel platform and are skipped. See Packaging.

Known limitations

  • ctypes dispatch costs more per call than a compiled extension; hot loops that cross the boundary per element will feel it. The bindings keep the per-call work small (prototypes and vtable addresses are resolved once, and the error check is inline), but each call still allocates its error slot, and each integer argument costs a range check.
  • A callback method that returns a structure needs libffi, which the runtime finds through the _ctypes extension or by name (ctypes.util.find_library("ffi")). A Python whose ctypes links libffi statically and hides its symbols, with no libffi installed, raises OSError the first time an implementation of such an interface is passed. The closures are built for the 64-bit platforms wheels target.
  • A typed-array parameter is copied into an array.array unless it already is one of the matching type code; a NumPy array is copied element by element.
  • The package’s namespace also holds the typing names the module imports (Any, Callable, ClassVar, Iterable, Iterator, Mapping, Sequence): a declared type with one of those names still works at run time, but type checkers reject the module.
  • A long-running callback stalls the producer thread that called it, and a callback that waits for the thread blocked in the calling Python code deadlocks.
  • LibraryLoadError is raised during the import, so it can only be caught as ImportError (the package isn’t importable to name the class).
