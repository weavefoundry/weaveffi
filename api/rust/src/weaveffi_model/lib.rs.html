1//! The WeaveFFI API model: everything between an API definition and code
2//! generation.
3//!
4//! * [`ir`] holds the in-memory IR types that an IDL document or a Rust
5//!   producer's metadata becomes, and [`parse`] reads the IDL text formats
6//!   (YAML and JSON), resolving imports.
7//! * [`validate`] checks a document against the library's
8//!   [`Identity`](pkg::Identity) and builds the one [`Model`](model::Model)
9//!   every generator consumes.
10//! * [`ty`], [`model`], [`abi`], [`errors`], and [`pkg`] hold the resolved
11//!   types and type index, the model with every C symbol and ABI signature,
12//!   the C type algebra, the error naming policy, and the package identity.
13//! * [`contract`] computes the contract, one fingerprint per declaration, so
14//!   a stale binding refuses to load and names what changed.
15//! * [`meta`] is the library metadata: the frames the producer macros embed
16//!   in a library and the CLI reads back into an [`Api`](ir::Api).
17//!
18//! # Features
19//!
20//! * `idl` (default): the IDL text formats, JSON Schema derivation for the IR
21//!   types, and fancy miette diagnostics. Without it the crate still provides
22//!   the IR, validation, the model, the contract signature builder, and the
23//!   metadata frames, which is all the producer macros need.
